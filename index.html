优化脉络 · 四条主线

1. 删冗余拷贝 / 去 host 同步

把逐元素 Python 循环、防御性 clone/contiguous、以及 .item() / torch.any / 隐式 reshape 造成的 device↔host 同步和多余带宽逐步消灭。

MTP verify 后 mamba 状态回写向量化（10x，e2e ≤3.54%）target_verify 去两次 contiguous()target_verify 去 conv_states 全池 cloneSSM 状态读写融合进 chunk fwd_h（原地更新）Triton track kernel 消除状态回写隐形拷贝气泡

2. 算子融合减少 launch

从 gating 三合一（HIP 上还有 prefill 形状版），到 MoE 门控、投影 GEMM 融合；conv 写出直接 split qkv、chunk stage-one 三合一分别写在 conv1d / chunk 状态那两篇。双流并发是融合的替代思路。

b.sigmoid+gdn_gating+unsqueeze 三合一（e2e ≤0.85%）shared expert 门控 sigmoid×mul 广播融合GDN 四路输入投影融合为单 GEMM（qkv/z/b/a）stride-aware kernel 重启投影融合GDN 双投影 alt-stream 并发 + 去 shared expert clone

3. 手写高性能 decode kernel

CUDA 侧 CuTe DSL 与 HIP 侧 inline ASM 是两个平台各自的 decode 递推终极优化，并伴随 BV / autotune 调参。

CuTe DSL 手写 GDN decode kernelHIP inline-ASM decode kernel + VK/KV 惰性布局切换fused_recurrent decode BV 8→32 调优

4. 状态布局与一致性

stride 解耦 → VK/KV 双布局 → 布局位图下沉进池。高性能布局的代价是状态一致性复杂度。

conv1d CUDA kernel 用负索引取 stride（布局无关化）HIP inline-ASM decode kernel + VK/KV 惰性布局切换修 prefix-cache 复用时 KV/VK slot_layout 失步
反复出现的 Trade-off 主题

CUDA/HIP 双路径分叉

把 Qwen3-Next 的 GDN 优化搬到 Qwen3.5，用 _is_hip 给 HIP 单独一套 kernel，换来 ROCm 上的 prefill/decode 提速。代价是两套数值路径、测试矩阵翻倍；HIP 路径后来出过精度问题，只能加 fallback。

优化引入的技术债

投影融合把 4 路 GEMM 收成 1 路，但融合输出是 strided 视图，下游 gating 按连续布局读就会算错。VK/KV 双布局让 HIP ASM decode 吃满带宽，布局元数据和状态搬运一旦失步就会静默损坏精度。高性能把正确性护栏从代码内移到了调用契约。

kernel 变体增殖

split_reshape_cat 从交错版 → contiguous 版 → v3（v_per_group=3），选择逻辑越来越复杂。

平台/形状条件启用

多数融合有 T>=64、hidden 阈值、head_dim==128 等启用门槛，短序列/异形状走 fallback，行为分叉。
