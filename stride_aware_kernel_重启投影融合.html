01

优化背景

做这件事的场景和动机

融合投影是 decode 延迟的关键优化，直接禁用损失太大；而问题本质不在融合而在下游 kernel 的布局假设。让 kernel stride-aware 是一劳永逸的解法——同时解锁"GEMM 输出零拷贝直接喂 gating"的完整链路。

02

好处与收益

  • 恢复投影融合的全部收益（BF16 4→1 GEMM / FP8 4→2），且不再需要任何 contiguous 物化。
  • gating 按错误 stride 读内存的精度问题修好，GSM8K 等回归对齐。
03

Trade-off

正确性债、分叉和退化
  • Split kernel 又多一个布局变体（交错版 vs. 连续版），调用方必须依模型正确选择——布局知识分散在 kernel 选择逻辑里（后来 Triton track kernel 消除状态回写隐形拷贝气泡 还要再加 v3 变体处理 v_per_group=3 的形状，变体继续增殖）。
  • Stride 参数化后 kernel 少了编译期常量寻址的微小优势，可忽略。
