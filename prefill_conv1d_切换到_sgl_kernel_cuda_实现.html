01

优化背景

做这件事的场景和动机

Qwen3-Next 上线初期，GDN prefill 的 profile 中 conv1d 占比偏高。sgl-kernel 中已经存在成熟的 CUDA causal_conv1d（供 Mamba2 类模型使用），支持 varlen + 连续批处理 + initial state，功能上完全覆盖 GDN prefill 的需求，因此可以零风险替换调用点（decode 的 causal_conv1d_update 路径不变）。

sgl-kernel 这条 CUDA 路径后来被明确限制为 CUDA-only。HIP / Qwen3.5 上的对应优化不是再换一套 conv 实现，而是把 conv 的写出和后面的 torch.split 收进同一个 kernel：decode 用 causal_conv1d_update_split_qkv，prefill varlen 用 causal_conv1d_fn_split_qkv（同时吸收原来的 transpose(0,1)）。旧路径 conv 后再 split q/k/v，会多三次拷贝。

02

好处与收益

  • Prefill 阶段 conv1d 算子耗时下降。
  • 消除了 Triton 路径每次调用的 host 侧 seqlens 计算与 batch_ptr H2D 拷贝。
  • HIP 路径上，decode 每层少三次 qkv split 拷贝；prefill 的 split 与输出重排不再单独物化。
03

Trade-off

正确性债、分叉和退化
  • 引入对 sgl-kernel CUDA 算子的依赖，非 CUDA 平台（ROCm/CPU/NPU）不能走该路径（后续改动明确将 sgl-kernel conv1d 限制为 CUDA-only）。
  • 双实现并存（Triton 版仍被 target_verify/decode 等路径使用），维护面变大：两个实现的语义（pad_slot_id、initial state 处理）必须保持一致。
  • HIP 再加一套 *_split_qkv kernel，CUDA sgl-kernel / Triton / HIP split 三条路径的 pad_slot、initial state、输出布局必须对齐；语义漂移会静默写错 q/k/v。
