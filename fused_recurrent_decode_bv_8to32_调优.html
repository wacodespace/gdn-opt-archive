优化背景

做这件事的场景和动机

Qwen3-Next decode 的 fused_recurrent kernel 沿用了 FLA 上游的保守默认值（BV=8 是为小 head_dim/小 batch 场景保并行度设的）。在 SGLang 的实际部署形状（HV=32、V=128、大 batch）下重新审视 occupancy vs. 每 program 工作量的平衡点即可得出更优配置。

02

好处与收益

  • GDN decode 递推 kernel 提速（机制上 program 数减 4x、q/k 复用增 4x）。
  • HIP / Qwen3.5 把同一思路做成 per-backend autotune：fused_sigmoid_gating_recurrent 上 CUDA 用 BV=8, nw=1, ns=3，HIP 用 BV=64, nw=4, ns=1；chunk_o 的 BV 在 HIP 上从 32 收到 16；chunk_gated_delta_rule_fwd_kernel_h 在 HIP 上用 BK=64（CDNA 的 LDS / 寄存器压力和 NV 不同）。
03

Trade-off

正确性债、分叉和退化
  • 极小 batch（N*HV*NV 铺不满 SM）时并行度下降 4 倍；decode 下 N*HV 通常仍够铺满。
  • 每 program 寄存器/共享内存占用增加，单 SM 并发 program 数下降；实测在目标形状上净收益为正。
  • tile 形状按平台写死两套，换 GPU 世代或 head_dim 必须重测；CUDA / HIP 最优 BV 已经反向（8 vs 64）。
