01

优化背景

做这件事的场景和动机

Qwen3-Next GDN prefill/混合 batch 场景。旧的映射表方案是从 vLLM 移植来的通用写法，为了让 grid 恰好等于总 chunk 数；但在 SGLang 的调用频率下（每层每 chunk 一次），host 准备成本 + H2D 传输 + 同步反而成了大头。序列长度 CPU 侧本来就有（extend_seq_lens_cpu），所以可以免费拿到 grid 所需信息。

02

好处与收益

  • causal_conv1d prefill 路径最多 9% 提速。
  • 消除每次调用的 D2H 同步点，对 overlap scheduler / CUDA graph 友好性也有改善。
03

Trade-off

正确性债、分叉和退化
  • Grid 第二维按最长序列取值：批内长度方差极大时会发射大量提前退出的空 program，浪费少量 launch 带宽（实测远小于旧方案的 host 开销）。
  • 删除了 metadata 预计算路径（PrepareMambaMetadata 的 nums_dict 机制），依赖该接口的调用方需要适配（接口留了 **kwargs 兼容吞掉旧参数）。
